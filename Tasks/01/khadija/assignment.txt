The Cliffhanger
what property would a language feature need, so cleanup still runs on every exit path — without you remembering a line?
-The language feature needs deterministic destruction bound to scope lifetime, widely known in C++ as RAII (Resource Acquisition Is Initialization). When an object leaves its enclosing block scope (whether through a normal return or an exception stack unwind), its destructor is guaranteed to run automatically to free resources. In modern C++, this is achieved using smart pointers like std::unique_ptr.

Code Review & Bug Hunting
1-If a malicious user sends a request with dataSize = -5, what happens to the server's memory? 

-The server will either throw a std::bad_alloc exception or crash immediately due to an Out-Of-Memory (OOM) error.
Why?
Becouse The memory allocation new int[dataSize] is written before the input validation check if (dataSize <= 0). The new[] operator expects an unsigned integer size argument (size_t). When the negative value -5 is implicitly cast to an unsigned integer, it wraps around to a critically large value on a 32-bit system. The system fails to allocate this impossible amount of memory, resulting in a denial-of-service (DoS) crash before the error check can ever be reached.
To fix it :we should Move the safety check if (dataSize <= 0) to the very top of the function before calling new int[dataSize].
